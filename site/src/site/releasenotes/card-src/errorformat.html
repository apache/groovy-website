The same diagnostics, in the shape the reader needs

A person reading a terminal and a log parser reading a build want different things from an error
FULL · THE DEFAULT, UNCHANGED 
Order.groovy: 2: unable to resolve class Custmer
 @ line 2, column 5.
       Custmer customer
       ^

Order.groovy: 3: unable to resolve class BigDecmal
 @ line 3, column 5.
       BigDecmal total
       ^
Four lines each, and the caret earns them. But the line number is repeated, the column arrives only on the second line, and no severity token appears at all.
SHORT · ONE LINE PER DIAGNOSTIC 
Order.groovy:2:5: error: unable to resolve class Custmer
Order.groovy:3:5: error: unable to resolve class BigDecmal
file:line:column: severity: message — the form editors, CI log parsers and coding agents already understand. The position is structural, so it is given once, with the column.
MEASURED · 14 TYPE-CHECKING ERRORS IN ONE SOURCE
73 lines under FULL → 17 under SHORT ·  set it with CompilerConfiguration.errorFormat, groovyc --error-format short, or <groovyc errorFormat="short">
FULL remains the default, byte for byte. SHORT is for whatever reads the log next.
