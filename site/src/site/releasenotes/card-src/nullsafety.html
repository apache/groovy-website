Dynamic idioms that cost nothing, compile-time checking, and facts no annotation can express
NULLCHECKER · COMPILE-TIME 
@Nullable String findBlurb() { null }
String shelve(String title) { ... }

String blurb = findBlurb()   // compile error
println shelve(findBlurb())  // compile error
Non-null by default, codebase-wide. With a suitable compiler config script, unannotated means non-null and the strict, flow-sensitive checker runs everywhere — no per-file annotations.
CONTRACTS · RUNTIME, AND PROVABLE 
@Requires({ a != null || b != null })
@NonNull static String pick(String a, String b) {
    if (a != null) return a
    return b   // premise + failed guard
}                // ==> b != null
There is no annotation for “at least one of these is non-null”. A precondition is just a boolean expression, so it says so directly — checked at runtime, and provable ahead of it.
